# Superadmin frontend v21 — Integration Guide

## 1. Version Changelog & Scope Summary

**Release target:** `frontend-superadmin-v21-ALL-RBGS-COMPLETE.zip` (name permitted only after the final source gate and packaging validation).  
**Input archive:** `frontend-superadmin-v20.zip`.  
**Mode:** V2.11 Mode B — Audit + Repair.  
**Approved repair plan:** two sequential RBGs; 24 findings across 9 source/documentation files.  
**Source change status:** RBG-01 and RBG-02 source/documentation changes completed; all plan findings closed in supplied scope. Test/build/browser execution remains explicitly deferred where host capabilities are absent.

### v20 → v21 changelog

- **RBG-01 — Users dirty-form confirmation closure (10 findings, 4 files):** corrected the Users Overview and Users Directory modals to await `confirmLeave(): Promise<boolean>` before closing a dirty form; added a single-flight close guard; retained synchronous clean-form close behavior; retained all form fields, schema, save callback and accessible custom confirmation dialog. Replaced the obsolete `window.confirm` test assumptions with translated custom-dialog regression coverage and added a Directory modal regression suite.
- **RBG-02 — Release documentation, token contracts and E2E guide (14 findings, 5 files):** rebuilt this guide under the six required V2.11 sections; added the 124-case route preservation matrix and 83-leaf feature-preservation inventory; rebuilt the current 181-item Section 43P evidence report and three physical cross-check tables; removed the obsolete empty duplicate Plans token inventory; populated Active Subscribers tokens from source evidence; corrected the E2E README's v21 title and route counts; replaced unsupported CRM mutation instructions with `CONTRACT_MISSING`.
- **Execution metadata:** the supplied archive's legacy root `progress.json` had inconsistent work-unit and RBG counters and references a 212-item historical ledger. It is execution state, not product source, and is excluded from the v21 ZIP. Current v21 execution state remains outside the release under `.ai_execution_state/frontend_superadmin_v20_to_v21/`.

### Frozen scope and preservation guarantees

- Only the supplied `frontend_superadmin` role module and its module-owned E2E/release documentation were in scope. Host root infrastructure, backend services, sibling roles, and unrelated role modules were not modified.
- The role has **14 domain containers** and **83 autonomous submodules**. All 83 are retained with their existing module documentation trio, host stubs and URL config.
- The route fixture retains **all 124 route-contract records**, including 42 intentional legacy aliases. There are 82 distinct canonical route path/marker targets across 13 route-bearing domains.
- The only application source changes are the two Users modal close handlers and their two co-located regression test files. The other five repaired files are release documentation/theme-contract/E2E documentation files.
- No production mutation endpoint, request/response schema, auth permission, tenant field, or CRM route has been invented. Existing preview-only and fail-closed API boundaries remain unchanged.

### Original audit handoff reconciliation

Grok's forensic report reported strong structure: 14 domains, 83 leaves, zero detected cross-submodule imports and complete documentation/stub/URL-config coverage. The independent Stage 2 audit agreed with those physical findings but discovered the Promise handling defect at both Users modal close call sites and the obsolete Overview test's dependency on `window.confirm`. The v21 source repair addresses that concrete gap; runtime results remain unclaimed.
