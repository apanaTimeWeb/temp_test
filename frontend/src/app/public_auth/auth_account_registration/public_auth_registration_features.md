# Public Auth Account Registration — Features

## 1. Purpose
Create a public account through the host-configured signup API. This autonomous submodule owns registration UI, client validation, mutation, local fixtures, and tests.

## 2. Route and destination
- Public route preserved: `/auth/signup` (host rewrite mapping must be merged/verified by host).
- Local Next route: `/frontend_public/public_auth/auth_account_registration`.
- Post-success destination preserved from source: `/superadmin/superadmin_setup-wizard`.

## 3. Fields (preserved)
`ownerName`, `libraryName`, `email`, `phone`, `password`, `confirmPassword`. Confirmation is client-only and excluded from the request payload.

## 4. Validation
Owner/library names require at least 2 characters; email uses Zod email validation; phone follows existing `+91` plus ten-digit pattern; password requires at least 8 characters, uppercase and number; confirmation must match. Messages are supplied through `next-intl` namespace `AUTH`.

## 5. API boundary
POST path comes only from `NEXT_PUBLIC_AUTH_SIGNUP_PATH`. Request fields are ownerName/libraryName/email/phone/password and Idempotency-Key is generated by the existing hook pattern. Backend envelope details remain host-contract dependent.

## 6. State and errors
Pending state disables fields and password toggles. Validation errors map known field names to localized generic copy; unknown fields and request errors use generic safe messages. Values remain available for retry.

## 7. Security
Never log passwords, phone or email. Do not invent endpoint paths or server-side auth/session behavior. Client role/navigation context is not authorization.

## 8. Dependencies
Next.js App Router, React Hook Form, Zod, TanStack Query v5, next-intl, Lucide, approved semantic theme tokens.

## 9. Tests
Harness contract and synthetic accepted/rejected fixture scenarios are local. Full test execution requires the host package manifest and test setup, absent from this archive.

## 10. Accessibility
Labels remain associated with all six inputs; errors are announced; password visibility controls have localized accessible labels and pressed state; keyboard focus rings use semantic tokens.

## 11. Theme contract
See `public_auth_registration_theme_contract.md`.

## 12. Forbidden patterns
See `public_auth_registration_forbidden.md`.

## 13. Known limitations
Host rewrite/live routing, backend schema, session behavior and actual MSW startup are not verifiable from this module archive.

## 14. Route ownership
No sibling submodule imports are used. The legacy dispatcher and flat implementation buckets are retired; the root page now redirects allowlisted view values to this child route, subject to host rewrite verification.

## 15. Retry behavior
Mutation errors preserve entered fields; idempotency key is cleared on edits and after success.

## 16. Payload contract
Confirmation password is never submitted. Request fields are copied from the existing implementation.

## 17. Localization
English and Hindi locale fragments are owned under `locales/`; the host next-intl provider must merge the module fragments into the `AUTH` namespace. The demo-fill label is localized in both languages.

## 18. Mock data
Fixtures use only reserved `.invalid` email and test-derived synthetic phone/password values. Fixtures do not imply a real account.

## 19. Scope boundary
This submodule does not own OTP/reset, recovery, login, or server session establishment.

## 20. Standalone Run/Mock Harness
`tests/harness/bootstrap.ts` records the required jsdom/Vitest/Testing Library setup. `mocks/handlers/PublicAuthRegistrationHandlers.ts` provides accepted, rejected, connection-failure, and invalid-envelope scenarios at a caller-supplied endpoint; the host test harness must register handlers explicitly. The host runner is not included, so execution remains `DEFERRED_TO_HOST_RUNTIME`.

## 21. Portability Guide
Copy this child folder under the host App Router path `src/app/frontend_public/public_auth/auth_account_registration/`. Supply the `@/*` import alias, React/Next.js, React Hook Form, Zod, next-intl provider merged with all four `AUTH` fragments, host `@/lib/api`, semantic design tokens, the configured `NEXT_PUBLIC_AUTH_SIGNUP_PATH`, and the preserved public route rewrite. The ambient declarations are type stubs only and do not replace actual host modules.

## 22. Evidence and Unresolved Contracts
Registration interaction tests live in `tests/PublicAuthRegistrationPage.test.tsx`. Request payload fields are preserved and `confirmPassword` remains client-only. The backend response envelope, server field-error schema, account activation semantics, idempotency support, and session side effects require host/backend confirmation.
